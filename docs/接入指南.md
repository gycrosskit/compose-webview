# WebView 接入指南

本库保留 core、Kuikly 与原生接线；根 CMP UI 已删除。各渠道实际消费与设备行为分别验收。

## 2.0.0 文件选择迁移

本版将三端文件／媒体选择交给宿主注入，属于行为不兼容升级。旧构造器和注册重载仍可编译，但未注入 provider 时文件请求会取消，不再启动组件内置选择器。升级 Maven、Git Pod 与 HAR 时须同步接线：

- Android 在 `registerGYWebView` 或原生能力入口传入 `AndroidWebFilePicker`。
- iOS 在创建 Renderer 前调用 `GYWebView.configureFileSelectionFactory`；工厂为每个 View 创建独立的 `GYWebFileSelectionProvider`，不要捕获已销毁 owner。原生 chooser 仍要求 iOS 18.4+。
- 鸿蒙在宿主 Creator 对应实例覆盖 `selectHostFiles`／`revokeHostFiles`，保持请求与文件 owner 一一对应。

宿主负责原生选择器、真实文件元数据和资源 lease；完成回调前先关闭系统呈现，按状态区分取消、拒绝、已阻止和策略限制。WebView 继续复核来源、文档、可见性、MIME／50 MiB 与一次交付；拍摄仍须同时启用 `fileChooserEnabled` 和 `mediaCaptureEnabled`。已交付文件在文档撤销时释放，不能因下一次选择取消或暂时隐藏提前删除。宿主可适配 Media 1.1.0，但 WebView 不直接依赖 media；实际系统选择、上传与设备权限须另行验收。

## 原生定位适配（未发布）

默认保持浏览器定位。宿主可对可信 HTTPS 初始主文档显式调用 `request.withNativeGeolocation()`；同时启用 JavaScript、`security.geolocationEnabled` 并配置可信来源。宿主必须处理 `NativeGeolocation` 通道的 `WebViewEvent.PageMessage`：用 `parseNativeGeolocationRequest` 解析，原生定位后通过 `replyPageMessage` 返回 `nativeGeolocationPositionReply` 或 `nativeGeolocationErrorReply`。位置回执必须保留真实 `accuracyMeters` 和采集 `timestampMillis`，不以交付时间冒充新位置。

`GetPosition` 携带网页的 `enableHighAccuracy`、`maximumAge` 与 `timeout`，由宿主明确选择策略；组件不将精度偏好变成必须授予精确权限。济世宿主按既有策略忽略前两项：允许 5 分钟内有效缓存、大概位置也返回，权限流程结束后才开始计算网页超时。这种适配不是严格浏览器定位实现，`maximumAge:0` 不保证新位置。组件未变更 location 或 permission 组件。

`watchPosition` 串行调用同一原生单次定位能力，完成后间隔 1 秒再采样，未变化的相同快照不重复通知；不是原生持续定位订阅。`clearWatch` 发 `Cancel`，宿主须取消对应 Job 并回复取消消息，释放通道回执。导航、销毁和页面归属撤销时清理该文档请求；暂时不可见不能清理已发出的权限流程，新权限 UI 仍由宿主可见性控制。`Unsupported` 也须消费并回复，不能以无限重试补注入。

Android 必须同时支持 `DOCUMENT_START_SCRIPT` 与 `WEB_MESSAGE_LISTENER`，仅 API 24 或 AndroidX 库版本不证明实际内核支持。适配脚本使用 `DOCUMENT_START_REQUIRED`，不在页面可见/完成后兜底安装。iOS 当前最低 15、鸿蒙最低 API 22 覆盖所用注入 API；三端仍检查原对象方法能否替换，失败时恢复原方法。仅接管获准初始主文档，不扩大到其他导航路径或 iframe，不替换 `navigator.permissions.query()`，不承诺 `instanceof` 等原生对象品牌。具体设备支持与权限行为须另行验证。

## 目录与接入边界

| 目录 | 职责 |
| --- | --- |
| `webview-core/` | UI 无关的请求、事件、安全策略、wire 协议及 Android 底层能力 |
| `webview-kuikly/` | Kuikly raw View DSL、KuiklyCompose入口与Android适配；传递KuiklyCompose/runtime，不引入第二套CMP UI |
| `ios/` | iOS Kuikly 的 WKWebView 原生接线 |
| `ohos/` | 自己封装 ArkWeb 的 HAR，不依赖社区 WebView 包 |

底层继续使用 Android WebView、iOS WKWebView 和鸿蒙 ArkWeb。KMP 产物是 AAR/KLIB；iOS 的 Kuikly 原生接线和鸿蒙 HAR 需要分别安装，不能用一个平台的编译结果代替另一个平台验收。

## Kuikly 原生注册与调用

Kuikly 原生 View 需要显式尺寸：

```kotlin
GYWebView {
    attr {
        size(320f, 480f)
        request(WebViewRequest(WebViewContent.Url("https://example.com/")))
    }
    event { onEvent { event -> /* 交给宿主 */ } }
}
```

通过 `ViewRef<GYWebView>` 调用 `goBack`、`goForward`、`reload`、`stopLoading`、`evaluateJavascript` 和 `exitFullscreen`。Kuikly 的返回值异步交付；`goBack` 回报是否消费返回，宿主据此决定是否退出页面。原生 View 名统一为 `GYWebView`，必须先完成对应平台注册。

Android 宿主在 `registerExternalRenderView` 中调用 `registerGYWebView()`；文件和媒体能力要求宿主提供 `ComponentActivity`。iOS 未发布候选应固定含所需修订的源码 commit，或在 Podfile 中用 `pod 'GYWebView', :path => '/path/to/compose-webview'` 显式消费本地源码；新版本发布后再固定其精确版本 tag。候选链接 `OpenKuiklyIOSRender 2.29.1` 和 `-ObjC`，由 Kuikly 按同名 Objective-C 类发现组件。旧 `0.2.0-rc.18` tag 仍依赖 Render `2.28.0`，不能用旧 Pod 验证候选。鸿蒙安装实际 HAR 并注册 Creator，见 [鸿蒙接入](../ohos/webview-native/README.md)。

iOS H5 视频页需在原生属性入口设置 `pictureInPicturePageActive=true`（默认 false），仅表示当前页面仍拥有播放会话；离页或加载失败先置 false，再更新 `visible`。宿主在 Info.plist 的 `UIBackgroundModes` 数组声明 `audio`。当前视频页退后台由 WebKit 接续自动 PiP，显式 `pageOwnerActive=true` 时，`visible=false` 保留业务 Bridge 和原文档初始化，但不允许发起新的采集权限 UI；离页继续隐藏并停媒。该接线已纳入 `1.1.0`，当前 `2.1.0` 候选继续保留；更早 Pod 需核对对应标签是否提供此属性；源码与替身回归不证明真机后台播放或 PiP 验收。完整合同见[全屏视频与 PiP 边界](功能与平台差异.md#h5-全屏视频控制)。

raw `GYWebViewAttr.pageOwnerActive(Boolean)` 和 `pictureInPicturePageActive(Boolean)` 提供类型化属性；KuiklyCompose 入口 `AppWebView` 可直接传同名参数。`pageOwnerActive=null` 不下发归属值，首次保留原生兼容行为；一旦显式启用，离页必须传 false，不能改传 null 来撤销归属。三端的 `pageOwnerActive` 表示：页面仍归属当前路由时为 true，真正离页、加载失败或归属失效时先设为 false，再更新 `visible`。打开系统选择器可能暂时令 `visible=false`；归属仍有效时，已有选择请求保留，成功结果等恢复可见后重新核验文档并交付。同 owner 的后台切换不旋转文档 nonce，不撤销 Bridge、pageMessage 和 JavaScript 回执，也不停止加载；新权限、文件选择或新窗口等 UI 动作仍要求可见。导航、请求变更、离页和销毁仍撤销旧请求。未设置该属性的宿主保持原有隐藏即撤销行为；不得把进程前后台状态当作页面归属。

`AppWebView.onViewUpdate` 在初始化与更新时先执行，可接线 `webContentVideoPlayer` 等宿主原生扩展属性；组件随后统一发送归属、PiP、可见性和 request，宿主不要在该回调重复注册 onEvent 或提交 request。需要在首个同步事件中访问节点时，也在此回调绑定宿主引用；`onController` 在 Composition effect 交接句柄，离开时回报 null。

Android Kuikly 视频全屏可在注册时传 `fullscreenOrientation = ActivityInfo.SCREEN_ORIENTATION_SENSOR_LANDSCAPE` 和 `fullscreenControlsFactory`。默认不改变宿主方向，也不创建业务控制 UI；factory 返回 `AndroidWebFullscreenControls` 的原生 View，与 Chromium 视频挂在同一 FrameLayout，避免宿主渲染层被 decor 视频盖住。组件负责退出时移除 View、恢复之前的方向/系统栏，触摸显示控制、3.5 秒隐藏和 500 ms 原生视频镜像；factory 的 actions 在退出后失效，宿主仍负责自身业务状态。ComponentActivity 的返回分发和 `goBack` 优先退出全屏。真实公开 API 接线见 [独立 Android consumer](../verification-consumer/src/kuiklyAndroidMain/kotlin/FullscreenConsumer.kt)。

公开接线示例（放在宿主现有 `IKuiklyRenderExport.registerExternalRenderView` 注册流程）：

```kotlin
import android.content.pm.ActivityInfo
import android.widget.TextView
import io.github.gycrosskit.composewebview.AndroidWebFullscreenControls
import io.github.gycrosskit.composewebview.AndroidWebFullscreenState
import io.github.gycrosskit.composewebview.kuikly.registerGYWebView

registerGYWebView(
    fullscreenOrientation = ActivityInfo.SCREEN_ORIENTATION_SENSOR_LANDSCAPE,
    fullscreenControlsFactory = { context, actions ->
        object : AndroidWebFullscreenControls {
            override val view = TextView(context).apply {
                setOnClickListener { actions.exit() }
            }
            override fun update(state: AndroidWebFullscreenState) {
                view.text = "${state.currentSeconds}/${state.durationSeconds}"
            }
        }
    },
)
```

示例 TextView 可替换为宿主既有播放器控件；控件 UI 与业务 owner 继续由宿主管理，组件只管理原生容器、视频镜像和生命周期。

`GYWebViewAttr.request` 仅变更 `navigationPolicy` 时，即时替换当前导航门禁并保留同一 WebView/DOM、文档 token 和待完成的安全能力请求；内容、settings、security、scripts 或资源规则变化仍沿用实例重建。商城 `HostSuffix("jd.com", scheme = "https", includeRoot = false, rejectUserInfo = true)` 同时要求 HTTPS、子域且无 authority userinfo（含空 `@`）；`rejectUserInfo` 默认 false 保留已有 URL 规则行为。`navigationOrigins` 可单独声明精确来源、限定端口的域后缀来源，以及 `hostSuffixAnyPortOrigins` 指定的不限端口域后缀来源；后者仍按 HTTP/HTTPS 协议区分，输入须使用默认端口，目标可使用任意有效端口。省略时保留历史 Bridge 导航限制，显式空集合拒绝主文档。来源策略不授予 Bridge 能力，Android 受限非 GET 导航仍会拒绝。

保持 DOM 的策略更新仍走现有属性入口：

```kotlin
request(currentRequest.copy(navigationPolicy = WebViewNavigationPolicy(
    blockedRules = listOf(WebViewUrlRule.HostSuffix(
        suffix = "jd.com", scheme = "https", includeRoot = false, rejectUserInfo = true,
    )),
)))
```

该例拦截商城子域并交给宿主路由；Bridge 的可信来源授权仍由原 security 决定。

## 导航与 JSBridge

当前Kuikly事件桥的handler返回Unit，没有导航decision返回协议。SDK Event.register(isSync)能改变调度，却不产生业务返回值，部分Android执行场景还会降为异步；不能据此宣称SDK永远无法扩展。拦截规则通过 `request.navigationPolicy` 预先下发，原生在首个请求前判断；`WebViewEvent.Navigation` 用于通知宿主已允许或已阻止的导航。外部跳转和业务路由仍由宿主执行。

`allowedOrigins` 只限制主帧，与 JavaScript/Bridge 开关独立；精确比较 scheme、host 和有效端口（HTTP 80、HTTPS 443），路径与查询不参与来源匹配。空集合不限制来源。可与 `blockedRules` 组合，让只读协议保持同源，同时把商城链接交给宿主路由：

```kotlin
navigationPolicy = WebViewNavigationPolicy(
    allowedOrigins = setOf("https://example.com"),
    blockedRules = listOf(WebViewUrlRule.Contains("/mall/")),
)
```

规则在三端原生同步执行，`Navigation(blocked = true)` 报告已拒绝的导航。HTML 仅保留当前加载的一次内部首航，后续 data 导航拒绝。以上策略可以在 `javaScriptEnabled = false`、Bridge 关闭时使用。

JavaScript、Bridge、文件选择和媒体采集需要显式开启；高权限能力需要可信 HTTP(S) 来源。低权限 `pageBridgeEnabled` 仅限初始精确同源页面，不能代替高权限来源授权。默认拒绝服务端证书错误；显式兼容设置见下文。HTTP 媒体采集仍受系统或内核限制。

iOS 最低为 15.0，但原生文件选择代理仅在 18.4 及以上可用。旧系统将本次 `fileChooserEnabled` 降级为关闭并报告 Unsupported，页面继续加载；DOM 交互拦截不能作为旧系统的原生安全隔离保证。需要严格禁止网页文件访问的宿主应限制系统版本或网页内容。

iOS18.4+ 的 Kuikly 原生入口接管 WKUIDelegate 原生文件请求；来源、主 frame、owner 和当前文档代次在原生复核。DOM 仅提供 accept/capture 的界面提示，不参与授权。拍摄需要同时开启 `fileChooserEnabled` 和 `mediaCaptureEnabled`，宿主声明 Camera/Microphone 使用说明。2.0.0 的原生选择器、文件读取与必要格式转换由宿主 provider 负责，WebView 不再内置拍摄或转码；适配 Media 1.1.0 时按其文件与编码合同返回结果。WebView 继续核验 MIME、50 MiB 限额及 owner／文档代次，拒绝或撤销时调用所属文件的 release。

网页相机/麦克风采集与文件拍摄均先检查来源、页面归属和系统权限；需要首次系统申请时先显示组件原生用途说明，确认并关闭说明后才继续。已授权直接执行，取消只结束本次，后续用户操作可再次申请。三端保留原生系统权限框；组件不把用途说明取消保存成拒绝。

`1.2.0` 候选新增该协议；设置 `request.permissionPresentation = WebViewPermissionPresentation.HOST` 可复用应用统一权限 UI；缺省 `NATIVE` 保留上述原生说明。HOST 模式收到 `PermissionExplanationRequested(requestId, permissions)` 后显示说明，确认且 UI 已退出后调用 `view.completePermissionExplanation(requestId, accepted)`；收到同 id 的 `PermissionExplanationCancelled` 必须取消该 UI。回执只对当前实例的当前请求单次有效，返回 true 仅表示受理，不代表授权；系统申请、来源/frame/文档/owner 复核仍由原生执行。隐藏、离页、导航或销毁会撤销等待，不能把旧确认用于新页面。组合权限可逐项复用应用已配置的说明回调，全部确认后才回执 true。升级时若使用 exhaustive `when (event)`，须补齐新增的两类说明事件分支。

`PermissionSettingsRequired` 由宿主决定是否展示应用设置入口，组件不会自动打开设置。Android 在请求入队时快照已有申请历史，仅后续真实拒绝、当前未授权、无 rationale 且非策略限制时提示，首次和同时排队的首次拒绝不提示；空回执不提示。iOS WebRTC 与文件拍摄仅在明确的应用权限 `denied` 时提示，`restricted` 不提示；WebRTC 的站点授权仍交给 WebKit 的 `Prompt`。鸿蒙仅根据实际拒绝且系统明确未显示授权框的回执提示，不凭普通拒绝推断永久禁止。旧 owner、文档和隐藏页面不交付设置提示。设置返回不自动重放拍摄或录音，网页再次请求时重新读取系统权限。

Android、iOS 与鸿蒙上传最多 10 个文件，每个须可读取且大小为 1 byte～50 MiB；MIME/type 按系统元数据与拍摄输出格式核验。鸿蒙普通选择走 DocumentViewPicker，`capture` 走系统 CameraPicker，照片 JPEG、视频 MP4，权限拒绝/取消/无效或迟到结果返回空列表。拍摄临时文件在成功交付后保留到文档导航、隐藏、请求切换或销毁，以供内核读取；失败立即清理。Android 和鸿蒙文件选择回调均不提供来源 frame，当前门禁只能检查可信当前主文档，不能证明请求来自主 frame。鸿蒙详见 [HAR 能力限制](../ohos/webview-native/README.md)。

商城接管可声明 `WebViewUrlRule.HostSuffix("jd.com", scheme = "https", includeRoot = false)`，同时限定 HTTPS、子域且排除父域；规则可经 wire 在原生同步判断，导航授权仍由独立 `allowedOrigins` 控制。

H5 通用入口为 `GYWebViewBridge.postMessage(handlerName, data)`，宿主收到 `WebViewEvent.BridgeMessage` 后自行解释业务命令。历史同义入口继续兼容；组件不提供登录 Token、账号或自动执行任意业务命令。鸿蒙通过原生投递到可信主文档的专用 MessagePort 通信，导航、输入变更、隐藏和销毁后撤销旧通道。

业务脚本用 `WebViewScript` 描述，默认仅在可信主文档执行；外部输入必须正确编码，不能拼入 JavaScript 源码。当前文档初始化允许在隐藏时执行，宿主的消息、权限与显式 JS 回执仍按可见生命周期撤销。显示无需 reload，也不会重复初始化脚本。

## 加载错误

### HTTPS 服务端证书兼容

`2.3.0` 已发布，不能使用旧坐标消费新设置；各渠道消费范围见[开发与验证](开发与验证.md)。`WebViewSettings` 新增 data class 字段会改变构造器及 `copy` 的二进制签名；原有源码调用可使用默认参数，但升级必须重编译全部调用模块，不承诺旧预编译调用方直接替换后的二进制兼容。旧 Tag、制品和历史验收保持原样，新版本各渠道消费须独立确认。

`WebViewSettings.verifyServerCertificate` 默认 `true`，旧 wire 未下发时也保持系统校验。宿主明确接受兼容风险时可设置：

```kotlin
WebViewSettings(verifyServerCertificate = false)
```

Android 在当前实例的 `onReceivedSslError` 调用 `proceed()`，iOS 仅对当前 WKWebView 的 ServerTrust challenge 使用服务端 trust credential，OHOS 在当前 render 的 SSL 错误回调调用 `handleConfirm()`。其他认证方式、失效实例、导航策略、Bridge/文件/相机/麦克风权限保持各自原有规则；该设置不提供客户端证书，也不能修复 TLS 协议/密码套件不兼容或绕过系统额外传输限制。

显式关闭后，过期、自签名、不可信根及主机名不匹配等服务端证书不再作为拒绝依据，可能接受中间人伪造的服务端。此项用于已授权的后端兼容阶段；后端证书与 HTTPS 部署优化完成后，由宿主统一恢复 `true`，不要把临时关闭视为长期证书治理方案。

宿主按 `WebViewLoadError.kind` 展示错误：三端网络超时统一为 `TIMEOUT`，TLS/证书错误统一为 `SSL`，其他网络错误为 `NETWORK`。`errorCode` 保留平台原始值供诊断，不应在业务页面重新分类；未知 iOS 错误域为 `UNKNOWN`。错误分类本身不改变证书兼容设置或导航策略。

## 具名早期双向页面通道

本 API 自 Maven/Git Pod rc.13 与 OHOS HAR rc.12 提供；本候选保留既有通道合同。本地源码替换不代替远程渠道验收。

```kotlin
val request = WebViewRequest(
    content = WebViewContent.Url("http://page.example/initial.html"),
    settings = WebViewSettings(javaScriptEnabled = true),
    pageMessageChannels = setOf("hostChannel"),
    navigationPolicy = WebViewNavigationPolicy(
        allowedUrls = setOf("http://page.example/initial.html"),
    ),
)
// Kuikly：命令经 render 异步交付，不能同步推断成功。
webView.replyPageMessage(message.replyId, replyData) { submitted -> /* 交给宿主 */ }
```

事件为 `WebViewEvent.PageMessage(channel: String, data: String, replyId: String)`。JS 形态为 `window.hostChannel.postMessage(string)`、`window.hostChannel.onmessage = event => ...`，回复正文位于 `event.data`。组件不解释 READY、challenge、验证码或其他业务字段。宿主应直接接新事件和回复 API，移除同名 JS facade，避免覆盖原生具名对象；协议版本、业务 owner、短握手超时、取消和业务请求仍由宿主负责。

频道名为 ASCII identifier `[A-Za-z][A-Za-z0-9_]{0,79}`，最多 16 个；保留的 frame/浏览器/既有 Bridge 名称不能用。消息和回复为 string，最多 64 KiB UTF-8；每个实例最多等待 128 个回复，满额拒绝新入站。replyId 对每条消息不透明且单次使用；Boolean `true` 表示平台已接受并提交，不证明 H5 或业务处理成功。该配置独立于 `pageBridgeEnabled`，只授予初始 HTTP(S) 页面低权限消息，不开启应用 Bridge、文件或媒体权限。

| 平台 | 实际支持与边界 |
| --- | --- |
| Android Kuikly | 必须支持 AndroidX `WEB_MESSAGE_LISTENER`；load 前注册，无 document-start 脚本依赖。每次声明内容加载和显式 reload 使用新物理 WebView，旧 owner 入站与 proxy 失效；同名 listener 不能在旧 WebView 上重新授权。 |
| iOS Kuikly Pod | WKUserScript 在业务 document-start 脚本前安装；声明内容加载和显式 reload 使用新物理 WKWebView，每文档闭包 nonce、真实主框架来源与完整 URL 门禁，排队回复再次核对 nonce。 |
| OHOS Kuikly HAR | v2实现使用 document-start 私有 capability + 文档 nonce，同步接收首段 string；单次回复走当前 Controller。隐藏/停止/导航撤销后只有显式 reload 新建物理 owner 才可恢复。尚未验证真实 ArkWeb 首段事件时序；空集合保持原行为。 |

新通道只服务初始完整地址，同时应用 `navigationPolicy`。iframe、外来源、旧文档、隐藏、取消、释放后的消息与回复拒绝。隐藏会永久撤销本轮通道，显示本身不会重新授权，需宿主显式 reload；非预期后续主文档导航同样撤销，不能依靠 `WebView.url` 把旧消息当作新文档消息。首段消息无需等待 `FirstContentVisible` 或 `PageFinished`，仍需组件在宿主中可见且业务 owner 有效。默认空集合沿用原有 Bridge、脚本、导航和能力生命周期。

Android API 来源见 [WebMessageListener](https://developer.android.com/reference/androidx/webkit/WebViewCompat.WebMessageListener) 和 [JavaScriptReplyProxy](https://developer.android.com/reference/androidx/webkit/JavaScriptReplyProxy)；组件的 owner 重建额外约束用于隔离旧同源文档。

## 升级边界

候选只维护 `io.github.gycrosskit.composewebview.kuikly.AppWebView` 与 raw `GYWebView`，根包的 CMP `AppWebView`、`AppWebViewState`、`WebViewCallbacks` 不再提供。旧 CMP 宿主应继续使用固定旧版本；迁至 Kuikly 时由宿主显式接线，不能把包名替换视为生命周期或导航决策等价。事件穷尽 `when` 仍须覆盖 `CapabilityUnsupported` 和 `PageMessage`；离开页面后不要向旧 controller 注入脚本。

## OHOS 工具链仓库

OHOS 使用 Kotlin `2.2.21-1.0.0`、Kuikly core `2.29.1-2.0.21-ohos` 与 render `2.29.1`。在 `pluginManagement.repositories` 添加 `https://maven.eazytec-cloud.com/nexus/repository/maven-public/` 以解析 OHOS Kotlin 插件，在依赖仓库添加同一地址以解析带 OHOS 变体的 Ktor/serialization；同时配置 Google、Maven Central 和腾讯 Maven。可逐项对照 [独立消费工程设置](../verification-consumer/settings.gradle.kts)，保留本组件的 JitPack 入口，不使用其本地 staging 路径。

OHOS 全屏窗口由 system-actions shared lease 执行。ArkWeb `onFullScreenExit` 无 handler/id，
主动退出后同 render 的下一次全屏须等待原生确认；未确认时新 handler 被退出，Window 已独立恢复。
新 request/Controller/render 清除旧确认门禁，旧 render token 无效；库不会用超时假定原生已经退出。

## 敏感页面与标准定位

在构造第一次请求时设置 `sensitiveDiagnostics = true`；高权限来源继续使用 `trustedOrigins`。
需要网页标准定位时显式设置 `security.geolocationEnabled = true`。Android 宿主声明
`android.permission.ACCESS_COARSE_LOCATION`，HarmonyOS 声明 `ohos.permission.APPROXIMATELY_LOCATION`
和原生用途说明。HOST 说明处理 `WebViewPermission.LOCATION`，确认说明不等于系统授权。

仅允许当前可信网页及其同源 iframe，跨源拒绝，不持久保存授权。iOS 沿系统 WKWebView 授权，由 App 配置
定位 purpose，H5 可直接使用系统定位；建议 H5 限制跨源 iframe。iOS 27+（SDK 27+ 编译）复用 NATIVE/HOST LOCATION 说明并返回 Prompt 交回系统，iOS 15～26 不提供该原生门控。完整差异见
[标准网页定位与敏感实例诊断](功能与平台差异.md#标准网页定位与敏感实例诊断)。业务初始化继续使用
`WebViewScript(..., injectionTime = WebViewScriptInjectionTime.DOCUMENT_FINISHED)`，无需新增定位 Bridge。

### HTTP 请求来源限制

`WebViewRequest.allowedHttpOrigins: Set<String>?` 支持以下选择，默认不增加 HTTP 来源拦截：

| 参数 | HTTP 加载行为 |
| --- | --- |
| `null` | 允许所有 HTTP 来源。 |
| `setOf("http://allowed.example.com")` | 只允许指定来源，按 scheme、host、有效端口精确匹配，不包含子域，路径不参与匹配。 |
| `emptySet()` | 拒绝所有 HTTP 来源。 |

宿主选择全部 HTTP 放行且不校验 HTTPS 服务端证书时，使用：

```kotlin
WebViewRequest(
    content = WebViewContent.Url("https://example.com"),
    allowedHttpOrigins = null,
    settings = WebViewSettings(
        verifyServerCertificate = false,
        mixedContentPolicy = WebViewMixedContentPolicy.ALWAYS_ALLOW,
    ),
)
```

HTTP 来源过滤、HTTPS 主文档加载 HTTP 子资源的 mixed-content 策略、服务端证书校验是三个独立设置；仅 `allowedHttpOrigins = null` 不会覆盖 mixed-content 限制。上例显式放行混合内容，组件的安全默认值保持不变。HTTPS 仍沿用既有导航与资源规则；HTTP 放行不授予 Bridge、脚本或权限能力，也不修改系统 ATS、Network Security Config 或 ArkWeb 安全设置。

字段同时下发 Android、iOS、OHOS 原生导航和可观察资源请求。iOS 在首次加载前安装 WKContentRuleList，规则编译失败拒绝加载；HTTP 例外不会撤销宿主拒绝规则或 mixed-content 限制。

限制：Android `shouldInterceptRequest` 仅报告资源初始 URL，不报告后续重定向，POST 主框架后续重定向也受系统回调可见性限制。因此 HTTPS 子资源重定向至 HTTP 或已允许 HTTP 来源重定向至其他来源不能由此字段保证拦截；Service Worker 等独立请求路径也不属于本实例回调合同。本字段不是完整网络隔离边界；需严格隔离时由宿主系统网络策略或受控网络代理落实。OHOS 的重定向/内核覆盖范围仍需目标 SDK 真机验收。三端均需消费包含该字段的新组件产物，旧原生版本可能忽略未知 wire 字段。
