# WebView 接入指南

当前 Maven / iOS Git Pod / OHOS HAR / OHPM 统一准备 `1.0.2` 未发布候选，精确依赖 SystemActions Native `1.0.1`；只包含 core、Kuikly 与原生接线；根 CMP UI 已删除。各渠道须分别通过构建与精确产物消费，旧版本验收不能证明本候选已可接入。公开消费与设备验收分别核对，详见 [README](../README.md) 与 [功能与平台差异](功能与平台差异.md)。

## 目录与接入边界

| 目录 | 职责 |
| --- | --- |
| `webview-core/` | UI 无关的请求、事件、安全策略、wire 协议及 Android 底层能力 |
| `webview-kuikly/` | Kuikly raw View DSL、KuiklyCompose入口与Android适配；传递KuiklyCompose/runtime，不引入第二套CMP UI |
| `ios/` | iOS Kuikly 的 WKWebView 原生接线 |
| `ohos/` | 自己封装 ArkWeb 的 HAR，不依赖社区 WebView 包 |
| `verification-consumer/` | 默认固定Maven坐标；显式verifyLocalSource才替换本库源码，verifyKuiklyCompose探测公开API |

底层继续使用 Android WebView、iOS WKWebView 和鸿蒙 ArkWeb。KMP 产物是 AAR/KLIB；iOS 的 Kuikly 原生接线和鸿蒙 HAR 需要分别安装，不能用一个平台的编译结果代替另一个平台验收。


## Kuikly 原生注册与调用

Kuikly 原生 View 需要显式尺寸：

```kotlin
GYWebView {
    attr {
        size(320f, 480f)
        request(WebViewRequest(WebViewContent.Url("https://example.com/")))
    }
    event { onEvent { event -> /* 交给宿主 */ } }
}
```

通过 `ViewRef<GYWebView>` 调用 `goBack`、`goForward`、`reload`、`stopLoading`、`evaluateJavascript` 和 `exitFullscreen`。Kuikly 的返回值异步交付；`goBack` 回报是否消费返回，宿主据此决定是否退出页面。原生 View 名统一为 `GYWebView`，必须先完成对应平台注册。

Android 宿主在 `registerExternalRenderView` 中调用 `registerGYWebView()`；文件和媒体能力要求宿主提供 `ComponentActivity`。iOS 未发布候选应固定含所需修订的源码 commit，或在 Podfile 中用 `pod 'GYWebView', :path => '/path/to/compose-webview'` 显式消费本地源码；发布后才固定 `1.0.2` tag。候选链接 `OpenKuiklyIOSRender 2.29.1` 和 `-ObjC`，由 Kuikly 按同名 Objective-C 类发现组件。旧 `0.2.0-rc.18` tag 仍依赖 Render `2.28.0`，不能用旧 Pod 验证候选。鸿蒙安装实际 HAR 并注册 Creator，见 [鸿蒙接入](../ohos/webview-native/README.md)。


iOS H5 视频页需在原生属性入口设置 `pictureInPicturePageActive=true`（默认 false），仅表示当前页面仍拥有播放会话；离页或加载失败先置 false，再更新 `visible`。宿主在 Info.plist 的 `UIBackgroundModes` 数组声明 `audio`。当前视频页退后台由 WebKit 接续自动 PiP，`visible=false` 仍撤销业务 Bridge 和新采集权限；离页继续隐藏并停媒。该接线仅存在于未发布源码候选，旧 Pod 不含此属性；源码与替身回归不证明真机后台播放或 PiP 验收。完整合同见[全屏视频与 PiP 边界](功能与平台差异.md#h5-全屏视频控制)。

原生 iOS 和 OHOS 的 raw `GYWebView` 可设置 `pageOwnerActive`：页面仍归属当前路由时为 true，真正离页、加载失败或归属失效时先设为 false，再更新 `visible`。打开系统选择器可能暂时令 `visible=false`；归属仍有效时，已有选择请求保留，成功结果等恢复可见后重新核验文档并交付。隐藏期间不接受新请求，导航、请求变更、离页和销毁仍撤销旧请求。未设置该属性的宿主保持原有隐藏即撤销行为；不得把进程前后台状态当作页面归属。

Android Kuikly 视频全屏可在注册时传 `fullscreenOrientation = ActivityInfo.SCREEN_ORIENTATION_SENSOR_LANDSCAPE` 和 `fullscreenControlsFactory`。默认不改变宿主方向，也不创建业务控制 UI；factory 返回 `AndroidWebFullscreenControls` 的原生 View，与 Chromium 视频挂在同一 FrameLayout，避免宿主渲染层被 decor 视频盖住。组件负责退出时移除 View、恢复之前的方向/系统栏，触摸显示控制、3.5 秒隐藏和 500 ms 原生视频镜像；factory 的 actions 在退出后失效，宿主仍负责自身业务状态。ComponentActivity 的返回分发和 `goBack` 优先退出全屏。真实公开 API 接线见 [独立 Android consumer](../verification-consumer/src/kuiklyAndroidMain/kotlin/FullscreenConsumer.kt)。

公开接线示例（放在宿主现有 `IKuiklyRenderExport.registerExternalRenderView` 注册流程）：

```kotlin
import android.content.pm.ActivityInfo
import android.widget.TextView
import io.github.gycrosskit.composewebview.AndroidWebFullscreenControls
import io.github.gycrosskit.composewebview.AndroidWebFullscreenState
import io.github.gycrosskit.composewebview.kuikly.registerGYWebView

registerGYWebView(
    fullscreenOrientation = ActivityInfo.SCREEN_ORIENTATION_SENSOR_LANDSCAPE,
    fullscreenControlsFactory = { context, actions ->
        object : AndroidWebFullscreenControls {
            override val view = TextView(context).apply {
                setOnClickListener { actions.exit() }
            }
            override fun update(state: AndroidWebFullscreenState) {
                view.text = "${state.currentSeconds}/${state.durationSeconds}"
            }
        }
    },
)
```

示例 TextView 可替换为宿主既有播放器控件；控件 UI 与业务 owner 继续由宿主管理，组件只管理原生容器、视频镜像和生命周期。

`GYWebViewAttr.request` 仅变更 `navigationPolicy` 时，即时替换当前导航门禁并保留同一 WebView/DOM、文档 token 和待完成的安全能力请求；内容、settings、security、scripts 或资源规则变化仍沿用实例重建。商城 `HostSuffix("jd.com", scheme = "https", includeRoot = false, rejectUserInfo = true)` 同时要求 HTTPS、子域且无 authority userinfo（含空 `@`）；`rejectUserInfo` 默认 false 保留已有 URL 规则行为。未发布的 `navigationOrigins` 可单独声明主文档精确来源和带 scheme、端口的域后缀来源；省略时保留历史 Bridge 导航限制，显式空集合拒绝主文档。来源策略不授予 Bridge 能力，Android 受限非 GET 导航仍会拒绝。

保持 DOM 的策略更新仍走现有属性入口：

```kotlin
request(currentRequest.copy(navigationPolicy = WebViewNavigationPolicy(
    blockedRules = listOf(WebViewUrlRule.HostSuffix(
        suffix = "jd.com", scheme = "https", includeRoot = false, rejectUserInfo = true,
    )),
)))
```

该例拦截商城子域并交给宿主路由；Bridge 的可信来源授权仍由原 security 决定。

## 导航与 JSBridge

当前Kuikly事件桥的handler返回Unit，没有导航decision返回协议。SDK Event.register(isSync)能改变调度，却不产生业务返回值，部分Android执行场景还会降为异步；不能据此宣称SDK永远无法扩展。拦截规则通过 `request.navigationPolicy` 预先下发，原生在首个请求前判断；`WebViewEvent.Navigation` 用于通知宿主已允许或已阻止的导航。外部跳转和业务路由仍由宿主执行。

`allowedOrigins` 只限制主帧，与 JavaScript/Bridge 开关独立；精确比较 scheme、host 和有效端口（HTTP 80、HTTPS 443），路径与查询不参与来源匹配。空集合不限制来源。可与 `blockedRules` 组合，让只读协议保持同源，同时把商城链接交给宿主路由：

```kotlin
navigationPolicy = WebViewNavigationPolicy(
    allowedOrigins = setOf("https://example.com"),
    blockedRules = listOf(WebViewUrlRule.Contains("/mall/")),
)
```

规则在三端原生同步执行，`Navigation(blocked = true)` 报告已拒绝的导航。HTML 仅保留当前加载的一次内部首航，后续 data 导航拒绝。以上策略可以在 `javaScriptEnabled = false`、Bridge 关闭时使用。

JavaScript、Bridge、文件选择和媒体采集需要显式开启；高权限能力需要可信 HTTP(S) 来源。低权限 `pageBridgeEnabled` 仅限初始精确同源页面，不能代替高权限来源授权。证书错误拒绝继续加载；HTTP 媒体采集仍受系统或内核限制。

iOS 最低为 15.0，但原生文件选择代理仅在 18.4 及以上可用。旧系统将本次 `fileChooserEnabled` 降级为关闭并报告 Unsupported，页面继续加载；DOM 交互拦截不能作为旧系统的原生安全隔离保证。需要严格禁止网页文件访问的宿主应限制系统版本或网页内容。

iOS18.4+ 的 Kuikly 原生入口接管 WKUIDelegate 原生文件请求；来源、主 frame、owner 和当前文档代次在原生复核。DOM 仅提供 accept/capture 的界面提示，不参与授权。拍摄需要同时开启 `fileChooserEnabled` 和 `mediaCaptureEnabled`，宿主声明 Camera/Microphone 使用说明；照片输出 JPEG，视频接受 MOV 时保留系统格式；本版在 MP4-only 时使用 AVAssetExportSession 导出真实 MP4。转换继承当前 owner、取消和临时文件清理门禁；输入与最终输出分别限制 50 MiB，临时转码磁盘占用不作严格上限承诺。

Android、iOS 与鸿蒙上传最多 10 个文件，每个须可读取且大小为 1 byte～50 MiB；MIME/type 按系统元数据与拍摄输出格式核验。鸿蒙普通选择走 DocumentViewPicker，`capture` 走系统 CameraPicker，照片 JPEG、视频 MP4，权限拒绝/取消/无效或迟到结果返回空列表。拍摄临时文件在成功交付后保留到文档导航、隐藏、请求切换或销毁，以供内核读取；失败立即清理。Android 和鸿蒙文件选择回调均不提供来源 frame，当前门禁只能检查可信当前主文档，不能证明请求来自主 frame。鸿蒙详见 [HAR 能力限制](../ohos/webview-native/README.md)。

商城接管可声明 `WebViewUrlRule.HostSuffix("jd.com", scheme = "https", includeRoot = false)`，同时限定 HTTPS、子域且排除父域；规则可经 wire 在原生同步判断，导航授权仍由独立 `allowedOrigins` 控制。

H5 通用入口为 `GYWebViewBridge.postMessage(handlerName, data)`，宿主收到 `WebViewEvent.BridgeMessage` 后自行解释业务命令。历史同义入口继续兼容；组件不提供登录 Token、账号或自动执行任意业务命令。鸿蒙通过原生投递到可信主文档的专用 MessagePort 通信，导航、输入变更、隐藏和销毁后撤销旧通道。

业务脚本用 `WebViewScript` 描述，默认仅在可信主文档执行；外部输入必须正确编码，不能拼入 JavaScript 源码。当前文档初始化允许在隐藏时执行，宿主的消息、权限与显式 JS 回执仍按可见生命周期撤销。显示无需 reload，也不会重复初始化脚本。


## 具名早期双向页面通道

本 API 自 Maven/Git Pod rc.13 与 OHOS HAR rc.12 提供；本候选保留既有通道合同。本地源码替换不代替远程渠道验收。

```kotlin
val request = WebViewRequest(
    content = WebViewContent.Url("http://page.example/initial.html"),
    settings = WebViewSettings(javaScriptEnabled = true),
    pageMessageChannels = setOf("hostChannel"),
    navigationPolicy = WebViewNavigationPolicy(
        allowedUrls = setOf("http://page.example/initial.html"),
    ),
)
// Kuikly：命令经 render 异步交付，不能同步推断成功。
webView.replyPageMessage(message.replyId, replyData) { submitted -> /* 交给宿主 */ }
```

事件为 `WebViewEvent.PageMessage(channel: String, data: String, replyId: String)`。JS 形态为 `window.hostChannel.postMessage(string)`、`window.hostChannel.onmessage = event => ...`，回复正文位于 `event.data`。组件不解释 READY、challenge、验证码或其他业务字段。宿主应直接接新事件和回复 API，移除同名 JS facade，避免覆盖原生具名对象；协议版本、业务 owner、短握手超时、取消和业务请求仍由宿主负责。

频道名为 ASCII identifier `[A-Za-z][A-Za-z0-9_]{0,79}`，最多 16 个；保留的 frame/浏览器/既有 Bridge 名称不能用。消息和回复为 string，最多 64 KiB UTF-8；每个实例最多等待 128 个回复，满额拒绝新入站。replyId 对每条消息不透明且单次使用；Boolean `true` 表示平台已接受并提交，不证明 H5 或业务处理成功。该配置独立于 `pageBridgeEnabled`，只授予初始 HTTP(S) 页面低权限消息，不开启应用 Bridge、文件或媒体权限。

| 平台 | 实际支持与边界 |
| --- | --- |
| Android Kuikly | 必须支持 AndroidX `WEB_MESSAGE_LISTENER`；load 前注册，无 document-start 脚本依赖。每次声明内容加载和显式 reload 使用新物理 WebView，旧 owner 入站与 proxy 失效；同名 listener 不能在旧 WebView 上重新授权。 |
| iOS Kuikly Pod | WKUserScript 在业务 document-start 脚本前安装；声明内容加载和显式 reload 使用新物理 WKWebView，每文档闭包 nonce、真实主框架来源与完整 URL 门禁，排队回复再次核对 nonce。 |
| OHOS Kuikly HAR | v2实现使用 document-start 私有 capability + 文档 nonce，同步接收首段 string；单次回复走当前 Controller。隐藏/停止/导航撤销后只有显式 reload 新建物理 owner 才可恢复。尚未验证真实 ArkWeb 首段事件时序；空集合保持原行为。 |

新通道只服务初始完整地址，同时应用 `navigationPolicy`。iframe、外来源、旧文档、隐藏、取消、释放后的消息与回复拒绝。隐藏会永久撤销本轮通道，显示本身不会重新授权，需宿主显式 reload；非预期后续主文档导航同样撤销，不能依靠 `WebView.url` 把旧消息当作新文档消息。首段消息无需等待 `FirstContentVisible` 或 `PageFinished`，仍需组件在宿主中可见且业务 owner 有效。默认空集合沿用原有 Bridge、脚本、导航和能力生命周期。

Android API 来源见 [WebMessageListener](https://developer.android.com/reference/androidx/webkit/WebViewCompat.WebMessageListener) 和 [JavaScriptReplyProxy](https://developer.android.com/reference/androidx/webkit/JavaScriptReplyProxy)；组件的 owner 重建额外约束用于隔离旧同源文档。

## 升级边界

候选只维护 `io.github.gycrosskit.composewebview.kuikly.AppWebView` 与 raw `GYWebView`，根包的 CMP `AppWebView`、`AppWebViewState`、`WebViewCallbacks` 不再提供。旧 CMP 宿主应继续使用固定旧版本；迁至 Kuikly 时由宿主显式接线，不能把包名替换视为生命周期或导航决策等价。事件穷尽 `when` 仍须覆盖 `CapabilityUnsupported` 和 `PageMessage`；离开页面后不要向旧 controller 注入脚本。

## OHOS 工具链仓库

OHOS 使用 Kotlin `2.2.21-1.0.0`、Kuikly core `2.29.1-2.0.21-ohos` 与 render `2.29.1`。在 `pluginManagement.repositories` 添加 `https://maven.eazytec-cloud.com/nexus/repository/maven-public/` 以解析 OHOS Kotlin 插件，在依赖仓库添加同一地址以解析带 OHOS 变体的 Ktor/serialization；同时配置 Google、Maven Central 和腾讯 Maven。可逐项对照 [独立消费工程设置](../verification-consumer/settings.gradle.kts)，保留本组件的 JitPack 入口，不使用其本地 staging 路径。


OHOS 全屏窗口由 system-actions shared lease 执行。ArkWeb `onFullScreenExit` 无 handler/id，
主动退出后同 render 的下一次全屏须等待原生确认；未确认时新 handler 被退出，Window 已独立恢复。
新 request/Controller/render 清除旧确认门禁，旧 render token 无效；库不会用超时假定原生已经退出。
