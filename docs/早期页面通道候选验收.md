## 公开 API 与职责

- `WebViewRequest.pageMessageChannels: Set<String> = emptySet()`。
- `WebViewEvent.PageMessage(channel, data, replyId)`。
- CMP `AppWebViewState.replyPageMessage(replyId, data): Boolean`。
- Kuikly `GYWebView.replyPageMessage(replyId, data, callback: (Boolean) -> Unit = {})`。
- JS `window[channel].postMessage(string)` 与 `.onmessage(event.data)`。

组件只交付低权限 string 消息和单次回复。回复 Boolean 表示原生受理，不能证明 H5 或验证码业务成功。宿主负责频道名、协议/challenge、业务 owner 与握手超时，并移除覆盖原生同名对象的 JS facade。见[接入指南](接入指南.md#具名早期双向页面通道源码候选)。

## owner 与文档边界

Android 使用 `WEB_MESSAGE_LISTENER`，不依赖 `DOCUMENT_START_SCRIPT` 或 JavascriptInterface。旧 provider 的具名 JS 对象按名称查 listener，因此 remove/re-add 同名 listener 不能隔离旧文档。启用通道时，声明内容变化和宿主显式 reload 均重建物理 WebView/WKWebView；替换前同步撤销旧 owner。只有初始完整 HTTP(S) URL 的真实主框架可进入，核对来源、owner、可见性和文档 nonce；iOS 排队回复再次检查 nonce。单次回复，UTF-8 每条 64 KiB，最多 128 条待回复。

隐藏、停止、失败、后续自发主文档导航和释放永久撤销本轮授权；show、H5 reload/history 不恢复。OHOS 非空通道明确拒绝整个请求并发送 `CapabilityUnsupported(PAGE_MESSAGE_CHANNEL)`，回复 false。默认空集合保留既有 Bridge、文件、脚本、媒体、全屏流程，不声称 OHOS 已实现早期通道。

rc.12 的 CMP forward/canGoForward、优先退出全屏再返回历史、共享异步退出脚本及取消重入保护完整保留。本轮另外修复独立复核发现的 rc.12 原生 Kuikly iOS 回执取消缺口：hide/换 owner/release 同步给挂起的 goBack/exitFullscreen 一次 false，晚 JS 不导航旧历史或写新 owner。原生 navigation 事件可同步换 request，继续处理前重查 owner/generation，避免旧事件撤销新 owner 首航授权。
