# WebView 开发与验证

源码构建与第三方远程安装是两个入口。日常接入见 [README](../README.md) 和 [接入指南](接入指南.md)。以下命令从仓库根目录执行。

工具链：Kotlin `2.2.21-1.0.0`、Kuikly `2.28.0-2.0.21-ohos`、CMP `1.10.3`。构建和设备验收分开记录；不要仅凭 KLIB 或 HAR 编译成功就删除应用中的旧组件接线。

AndroidX Activity 会传递稳定性注解包，该包不含 Compose UI 或执行运行时；独立消费者的门禁仅放行这两个注解模块。其他 Compose UI/runtime 依赖仍会使 Kuikly 验证失败。

本地 Maven 打包执行 `bash scripts/package-maven.sh`。JitPack 使用 macOS 预构建归档和 SHA-256 校验；`release-checksums.txt` 保存不可变标签的真实归档校验值。远程消费者使用 `-PremoteOnly -PwebViewVersion=0.2.0-rc.4`，该模式仅从 JitPack 读取本组件。HAR 的 ohpm 审核状态须查询 registry 并实际安装确认；同标签 GitHub Release 的 HAR 可用于审核期间的远程预发布验收。

详细结果见 [VALIDATION](../VALIDATION.md) 与 [HAR 验证](../ohos/VERIFICATION.md)。Maven、iOS 原生 Pod、OHPM HAR 各自验收；已公开的 `@gycrosskit/webview@0.2.0-rc.2` 可从 Registry 安装，GitHub Release HAR 下载不等于 Registry 安装。

Kuikly 独立消费者最终链接时，device 与 simulator 分别传 `-PrenderFrameworkDir` 和 `-PsimRenderFrameworkDir`，值为相应 `OpenKuiklyIOSRender.framework` 的父目录；只提供 device 搜索路径不能证明 simulator 链接。

## iOS 布尔回执与资源规则回归

```bash
WEBVIEW_IOS_SIMULATOR_RENDER_FRAMEWORK_DIR=/path/to/simulator/Render/parent bash scripts/verify-ios-wire.sh
```

测试在 UIApplication Simulator App 内直接编译生产 `GYWebView.m`，链接真实 `OpenKuiklyIOSRender`，不替换 Render/JSON/WebKit。核验导航的允许/阻止、主框架/手势、存在/缺失 WKWebView 的命令结果在 Foundation JSON 往返后仍为 CFBoolean；安全开关只接受真实 JSON Boolean。资源规则捕获生产生成的 JSON，检查大小写开关和 host/port/path 边界，然后交给真实 WKContentRuleList 编译器，覆盖 contains/exactHost/hostSuffix。SDK 需要 iOS15+；当前实际 Simulator 运行不代替最低系统和真机验收。

Objective-C 的 `!`、`&&` 和比较结果类型为 int，直接 `@(...)` 会编码成数字0/1。Kuikly wire 严格要求 Boolean，所以原生显式使用 `@YES/@NO`，不放宽解析器掩盖生产者错误。WebKit 的内容规则正则只支持 [官方规定的子集](https://webkit.org/blog/3476/content-blockers-first-look/)；用可选路径和末尾锚点替换不支持的 `|`，同时避免 host 前缀误匹配。
