## Android viewport 验收

本版布局修复只设置公共 `AppWebView` 的原生布局参数，编译与 Android 单元测试走现有 `Source regression / android`；JVM WebView 替身不执行 Chromium，不能验证 CSS `100vh`。

使用新远程 Maven 产物在实际 WebView 内核上验收：先给 Compose 固定宽高的有界区域，比较原生 measured size、`window.innerHeight`、`100vh` 元素及 Bootstrap 蒙版的 `getBoundingClientRect().height`；加入超出 viewport 的长页，检查页面内部滚动且 Compose 区域不增长；再将区域收起到 0 并隐藏，恢复原尺寸和 visibility，确认 viewport/蒙版恢复、WebView 实例未替换且页面未重载。至少覆盖已复现的 WebView 97 与当前内核；这些真实内核检查属于宿主/设备验收，结果须另记收据。

## iOS 布尔回执与资源规则回归

本版远程调试沿用此真实 WKWebView harness 检查新建实例的 `inspectable`。默认 `WEBVIEW_DEBUG_BUILD=0` 验证关闭，再传 `WEBVIEW_DEBUG_BUILD=1` 验证开启；两次均需实际 Simulator 执行，不用源文本匹配代替属性结果。

`Source regression / native` 只构建一次固定版本 Renderer，在 iOS 16.4+ Simulator 复用同一 `Products` 执行两档 harness，分别保存 `ci-diagnostics/ios-wire-release.log`、`ios-wire-debug.log`。脚本要求真实属性断言产生对应 `PASS: Native inspectable policy DEBUG=0/1`，旧系统跳过 availability 分支不算通过。此 harness 检查 Kuikly Native Pod 的生产 Objective-C 接收端；CMP 的 Kotlin/Native Debug/Release binary 策略仍需各自链接与运行验证。

```bash
WEBVIEW_IOS_SIMULATOR_RENDER_FRAMEWORK_DIR=/path/to/simulator/Render/parent bash scripts/verify-ios-wire.sh
```

测试在 UIApplication Simulator App 内直接编译生产 `GYWebView.m`，链接真实 `OpenKuiklyIOSRender`，不替换 Render/JSON/WebKit。核验导航的允许/阻止、主框架/手势、存在/缺失 WKWebView 的命令结果在 Foundation JSON 往返后仍为 CFBoolean；安全开关只接受真实 JSON Boolean。资源规则捕获生产生成的 JSON，检查大小写开关和 host/port/path 边界，然后交给真实 WKContentRuleList 编译器，覆盖 contains/exactHost/hostSuffix。SDK 需要 iOS15+；当前实际 Simulator 运行不代替最低系统和真机验收。

Objective-C 的 `!`、`&&` 和比较结果类型为 int，直接 `@(...)` 会编码成数字0/1。Kuikly wire 严格要求 Boolean，所以原生显式使用 `@YES/@NO`，不放宽解析器掩盖生产者错误。WebKit 的内容规则正则只支持 [官方规定的子集](https://webkit.org/blog/3476/content-blockers-first-look/)；用可选路径和末尾锚点替换不支持的 `|`，同时避免 host 前缀误匹配。
