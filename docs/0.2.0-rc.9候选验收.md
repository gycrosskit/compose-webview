# WebView 0.2.0-rc.9 候选验收

2026-10-05：Maven、Native Pod 和 Web HAR 的候选版本统一为 `0.2.0-rc.9`；Web HAR 精确依赖 `system-actions-native 0.2.0-rc.4`。本记录保留标签创建前的本地候选验证。随后已完成发布与远程消费，见[rc.9 远程发布验收](0.2.0-rc.9远程发布验收.md)；宿主设备验收仍独立。

## 修复与审查

- CMP Android/iOS 业务 Bridge 复核当前 owner、可见性与文档 token；导航、隐藏和释放撤销旧回执。同源替换不能沿用旧 token。禁用 JavaScript 时不注入声明式业务脚本。
- Android Client/Chrome/public failure 与 popup 同时检查当前 owner/release；已移出的 popup 不再派发迟到导航。回调同步关闭页面后，不继续执行旧实例脚本/原生动作。
- iOS 保持最低 15.0；公开 WKUIDelegate 文件代理要求 18.4+，低系统开启受控 chooser 明确拒绝并发出 `FILE_CHOOSER` Unsupported。原生来源授权检查 securityOrigin、主 frame、owner 与文档代次；DOM 仅提供有界的 accept/capture 界面提示。
- iOS CMP/Kuikly 使用 UIKit DocumentPicker/Camera，OHOS 使用 DocumentViewPicker/CameraPicker；取消与迟到结果一结算。每项可读文件限 1 byte～50 MiB，最多 10 项；拍摄格式按真实 JPEG、MOV/MP4 输出核验，失败及时清理。成功拍摄文件保留到文档撤销，后续 chooser 取消不会删除旧上传。
- Issue #4 的实际 HTTPS 商城子域、排除父域需求由 `HostSuffix(suffix, scheme, includeRoot, rejectUserInfo)` 表达，三端 wire 保留；`allowedOrigins` 独立控制导航来源。来源解析拒绝凭据/空 userinfo，回归保留 exact IPv6、IPv4 mapped IPv6 与合法非默认端口；展开/压缩 IPv6 与 JS hostname 使用同一规范表示，DOM 与 document-start 规则保留既有 DNS 末尾点归一化；HostSuffix 仍沿用 DNS 域边界和不限 HTTPS 端口的契约。

- Android Kuikly 全屏复用宿主原生 controls factory 和方向声明，视频/控件同容器；恢复进入前窗口/方向，退出后旧动作与同步重入回调失效。镜像结果限制长度、三项真正类型与有限数字，CMP 同契约。
- Kuikly 仅更新 navigationPolicy 保留实例、DOM 与安全 owner；三端当前导航使用新策略，待完成 Bridge/chooser/媒体仍遵守原安全边界。

完整自有生产源码、资源、配置、命令和实际 caller 已逐文件审查，任务证据位于本地 `build/full-review/coverage.json`（文件 SHA-256、平台、reviewed、入口/caller/失败与生命周期摘要；不提交生成证据）。范围包含 common core、CMP Android/iOS、Kuikly common/Android、Objective-C、ArkTS/TS、全部 bootstrap、来源/资源规则、Manifest/资源、原生 helper 及发布/消费命令。第三方 SDK 内部由其供应方负责，system-actions 实现由对应任务独立审查。

## 尚未验证与平台边界

- 未执行 Android/iOS/OHOS 真机的相机录制、权限弹窗/设置恢复、H5 HTTP 上传、后台/旋转与宿主业务验收。真实 JPEG 编码证明原生输出链路，不代表相机设备验收。
- iOS15～18.3 缺少公开原生上传拦截 API，关闭文件能力时的 DOM 兼容拦截不能保证默认 WebKit 上传行为被原生隔离。需要这种隔离的页面必须使用 iOS18.4+；常规网页仍支持 iOS15。
- HarmonyOS fileSelector 没有真实来源 frame 或独立 gesture 信息，只能证明当前可信且就绪的主文档；不能称为来源 frame 证明。
- Native UIKit 视频沿用 QuickTime MOV；仅接受 MP4 的 capture 输入会拒绝，不做格式改名或伪转换。
- Git 标签、Release/JitPack/Git Pod/Release HAR 的干净远程消费已由[远程发布验收](0.2.0-rc.9远程发布验收.md)分别核实；OHPM 审核/Registry 可用性与宿主设备接入仍独立。历史 rc.8/rc.7 验收不能替代当前候选。
