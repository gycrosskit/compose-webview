# 0.2.0-rc.18 发布验收与边界

Maven / GYWebView Git Pod 使用不可变版本 `0.2.0-rc.18`。版本公开状态以 [Release](https://github.com/gycrosskit/compose-webview/releases/tag/0.2.0-rc.18)、`maven-provenance.json`、`release-verification.json` 与实际 CI 收据为准。

## 本版能力

PR43 将 H5 视频脚本、镜像解析与时间格式归入 core，共用 Android 默认原生控件 `AndroidDefaultWebFullscreenControls` 和 KuiklyCompose `FullscreenPlayerOverlay`。Android 通过既有 factory 显式注入，空 factory 保持旧行为；宿主继续拥有页面生命周期、文案、方向、录屏、学习与问卷逻辑。源码门禁 run [38050803508](https://github.com/gycrosskit/compose-webview/actions/runs/38050803508) 在精确 SHA `a2f4c4bfafb4361bc6c7b9ad00a1ae5fd64296aa` 实际执行 Android 113 与 iOS 99 项测试、iOS Debug/Release wire。

iOS/OHOS 原生源码未改。新 Git Pod 用精确 tag/version/source bytes 核验，宿主也可继续使用已验收 rc.17 Pod；OHOS 沿用 HAR rc.14 与 system-actions-native rc.4，不重复空发 HAR/OHPM。HAR 从 [rc.16 Release](https://github.com/gycrosskit/compose-webview/releases/download/0.2.0-rc.16/WebViewNative.har) 获取并校验既有摘要。

## 冻结与远程验收

独立 release 分支一次准备版本、API probes、workflow 与当前文档。Source regression 的 `package_maven=true` 在 macOS 保留源码门禁，检查完整 17 publications、变体、内部精确依赖及 sidecars，然后归档真实字节并生成来源收据。整次 run 成功后冻结 checksum，发布准备 PR 门禁成功才合入 main、创建 tag 与 Release；上传与原归档完全相同的字节，不覆盖旧标签或资产。

Release validation 自动为 rc.18 启用 FullscreenControls、KuiklyCompose、pageChannels 与 navigation；旧 RC 条件保留。公开 JitPack 逐 publication/variant 下载并核验实际 size/hash；消费者使用 `remoteOnly`，Android 分别编译 CMP/Kuikly 并做 D8/依赖门禁，Native 编译 iOS 三架构与 OHOS KLIB，Kuikly iOS 新 API 最终链接真实固定 Renderer，CMP 独立最终链接。Git Pod 核验精确 tag/version/native source，并构建真实 Simulator framework。

归档 source SHA、最终 tag SHA、archive SHA-256、workflow/jobs 与 probes 执行结果保存在外部收据。文档/checksum 收尾与归档 SHA 的生产源码必须相同。

2026-10-10 归档 [run 38052723148](https://github.com/gycrosskit/compose-webview/actions/runs/38052723148) 全部 4 jobs 成功，source SHA `e0429f5a1df54556708c1275c31dc8cb10d019c1`。Android 113 与 iOS 99 项测试实际执行且无失败、错误或跳过，真实 Debug/Release wire 通过。归档 2,347,299 bytes，SHA-256 `e488e73297a2b4d5149e26396b2e1c08175609fc0fa256ccdc410459ea4c6982`；下载后再次检查 17 publications、平台变体、内部精确依赖和四种 sidecars 全部通过。

## 未覆盖范围

iOS common overlay 不能保证覆盖系统播放器，OHOS 原生全屏层级/触控/旋转/前后台需要设备验收。OHOS KLIB compile 不等于 HAP/HAR final link 或业务验收；Git Pod framework build 与 iOS consumer link 不等于宿主最终 Debug/Release binary 的设备运行。JitPack 公开 SHA-256/SHA-512 sidecar 的 404 按渠道边界记录，variant metadata 声明哈希仍全部校验。
