# 0.2.0-rc.16 发布验收与边界

Maven 和 GYWebView Git Pod 使用 `0.2.0-rc.16`，从已通过 PR 门禁的最终 main 合并提交创建不可变标签。OHOS 源码自 rc.15 未变化，继续复用 HAR `0.2.0-rc.13` 与 system-actions-native `0.2.0-rc.4` 原字节；不重新构建、不重发 OHPM、不覆盖旧标签。

## 本版修复

- [#36](https://github.com/gycrosskit/compose-webview/pull/36)：Android CMP/Kuikly 补查主文档非 GET 请求。Android WebView 不为 POST 调用 shouldOverrideUrlLoading，shouldInterceptRequest 仅观察重定向首地址；307/308 保留 POST 时无法证明后续来源仍合法。因此配置 allowedUrls、allowedOrigins、blockedRules 或限制 HTTP(S) scheme 时，合法同源 POST 也保守拒绝并报告 Navigation(blocked=true)。默认策略 POST、iframe/XHR 保持原行为；不把 POST 改写为 GET。
- [#37](https://github.com/gycrosskit/compose-webview/pull/37)：初始 URL 与页面通道的文档身份采用同一规范化合同，保留 path/query/fragment 原字节和 allowedUrls 原字符串匹配。
- [#38](https://github.com/gycrosskit/compose-webview/pull/38)：iOS 两入口在 JavaScript 关闭时仍可运行内部全屏退出恢复脚本，页面业务脚本开关保持其原合同。

## 发布核验

冻结 Maven 归档通过 scripts/package-maven.sh 生成，scripts/check-maven.py 核验17 publications、POM、Module Metadata、平台变体、精确内部版本和哈希 sidecar；release-checksums.txt 固定归档 SHA-256。

发布后运行既有 Release validation：verify-public 先验证不可变 tag/commit、冻结归档和全部公开文件；release-android 编译 CMP-only/Kuikly-only 精确远程依赖，release-native 编译 iOS/OHOS 并链接 CMP Simulator Framework。rc.16 已加入既有页面通道、导航和 KuiklyCompose API probe 条件。PR 事件中的轻量成功不算远程消费。

GYWebView Git Pod 需在新消费目录核对 Podfile.lock 的精确 tag/commit，并使用真实 OpenKuiklyIOSRender SDK 完成 UIKit App 最终链接。OHOS 需下载原 Release HAR、校验原 SHA、查询并精确安装 Registry rc.13，分别记录各渠道结果。

本次可复核日志、JSON 和资产位于组件工作区 reports/2026-10-09-tests-webview-release；发布结果见[精确 Release](https://github.com/gycrosskit/compose-webview/releases/tag/0.2.0-rc.16)与其 Release validation runs。源码合同、构建、远程消费及设备/业务是独立证据；没有执行的项目不声明通过。

未执行 Android/iOS/OHOS 真机、真实 H5 POST/307/308、验证码、权限和宿主业务验收。受限页面需要合法 POST 时须先评估上述保守拒绝的兼容性成本。
