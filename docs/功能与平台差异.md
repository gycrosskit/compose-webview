## 公开功能与合同

- `AppWebView(request, visible, modifier, onEvent, onController)` 直接复用 raw `GYWebView`。等值 request 不重发；navigationPolicy 单独变化保留当前文档；hidden 撤销受控能力，移除先关闭回调归属再 stop。controller callback 更换交接句柄，不销毁原生节点。CMP `AppWebViewState` 属于组合位置，不能跨页面共享。
- `WebViewNavigationPolicy` 默认 HTTP/HTTPS，popup 默认拒绝；`allowNewWindows=true` 时所有端当前均路由到原页，没有多Tab UI。Android `supportMultipleWindows` 是捕获 popup 的原生 flag，iOS/OHOS不消费该flag。
- `WebViewSecurity` 高权限开关默认false。导航允许不等于Bridge/文件/媒体授权；可信HTTPS、主frame、可见性、owner和代次分别检查。脚本默认只在可信主文档执行；document-start的Android内核支持和fallback需区分。
- `pageMessageChannels` 默认空，最多16个合法名，单条UTF-8至多64KiB。只赋予初始完整HTTP(S)文档 capability；隐藏/停止/导航/释放撤销，恢复通道须显式reload。`replyPageMessage=true` 表示当前单次请求已受理，不是H5交付/业务ACK。
- `goBack` 优先退出全屏；back/exitFullscreen 待处理命令失去owner时false结算一次。`evaluateJavascript` 旧owner结果允许丢弃，不承诺所有命令都有false回执。progress、title、error、history、Navigation/PageMessage等是观察状态，不是业务成功。
- `stopLoading` 撤销当前异步 JS/全屏回执、文件选择及媒体权限业务请求；文件以 null、待处理全屏命令以 false 至多结算一次。实例仍可 reload 或发起新操作；旧系统选择器/权限结果返回前保留归属门禁，不撤回已授予的系统权限。取消回执重入的新请求不属于旧 stop。
- `clearResourceCache`/`clearWebsiteData` 是进程级清理，没有按origin参数。取消等待不撤销系统删除；宿主应停止其他页面继续写入。

### Android viewport 布局

CMP Android 的公共 `AppWebView` 在创建原生 WebView 时使用 `MATCH_PARENT × MATCH_PARENT`。旧 Chromium 在原生 `WRAP_CONTENT` 下可能把 CSS viewport 高度归零，即使原生 measured height 正常，`100vh` 和依赖它的蒙版仍会是 0。宿主应通过 Compose `modifier` 提供有界尺寸；原生子 View 填充该区域，长页面由 WebView 内部滚动，不按 HTML 内容高度扩张。`configure` 若重设 `layoutParams`，将覆盖组件默认策略。

Kuikly Android 已使用 `MATCH_PARENT`；iOS 随父 View bounds、OHOS 使用 `100%`，本版保留这些入口的既有布局策略。隐藏仍只同步原生 visibility，不引入重载或宿主监听。此修复自 Maven `0.2.0-rc.17` 提供；有界区域、长页滚动、0 尺寸隐藏后恢复和真实旧内核仍须消费新远程产物验收，不能用源码检查或 JVM WebView 替身证明 CSS viewport 已恢复。

### WebView 远程调试

本版在 iOS 16.4+ 为每个新建 `WKWebView` 设置 `inspectable`：CMP 按最终 Kotlin/Native binary 的 `Platform.isDebugBinary`，Kuikly Native Pod 按 `DEBUG` 编译条件开启，非 Debug 显式关闭。旧系统不调用新增属性，仍由系统决定开发检查能力。此策略自 Maven/Git Pod `0.2.0-rc.17` 提供；公开产物消费与宿主最终 Debug/Release binary 的实际运行仍须分别验收。

Android、鸿蒙是进程级 SDK 开关，由宿主在创建网页前分别调用 `WebView.setWebContentsDebuggingEnabled(appIsDebug)` 和 `WebviewController.setWebDebuggingAccess(appIsDebug)`。不要依赖组件库自身的 BuildConfig 或较新 Android 内核的自动开启行为；该开关只提供开发工具检查能力，不改变网页布局或 JSBridge 授权。

## 差异分类与使用边界

| 分类 | 当前合同与限制 |
| --- | --- |
| 组件接口缺口 | CMP `onNavigationRequest`可同步按任意宿主状态返回ALLOW/BLOCK；Kuikly是Unit observer，native先决定再通知。Kuikly SDK2.28 `Event.register(isSync)`确有同步调度，但handler/native callback无业务返回值，`onFireEvent:Boolean`仅表示是否找到handler；Android同步调度在主队列任务中还能降为异步。当前桥没有导航decision返回协议，不等于SDK永久无法扩展。声明policy覆盖预先拦商城再观察的共同子集；取消后异步重放会改变POST/重定向/headers/gesture/history，不能称等价。 |
| 组件接口缺口 | CMP typed state/兼容同步Boolean与Kuikly rawJSON/异步controller不同；Kuikly没有CMP `pageEnteredAtMillis`外部前置时点输入。 |
| OS/SDK边界及当前缺口 | iOS未实现DOM Storage关闭、每实例third-party cookie、完整禁图false、Android按钮/宽视口/overview、textZoom/fontScale/算法暗化。`loadsImagesAutomatically=false`存在data:image绕过，不能宣称全禁图。 |
| OS/SDK边界 | OHOS仅有`WebCookieManager`静态全局third-party cookie控制，没有当前每实例映射。true明确拒绝；false/默认也不能隔离同进程其他Web对全局策略的修改，组件不修改全局策略冒充per-view保证。 |
| OS/SDK边界 | OHOS `allowFileAccess`默认false、true仅放行沙箱file子资源，blockedResourceRules仍优先；顶层file/content/resource仍拒绝，`allowContentAccess=true`无Android content provider等价。iOS这两开关true明确拒绝。 |
| HTML输入范围 | 两iOS入口使用WK loadData+IANA/Foundation无损编码：未知charset或内容不可表示为LOAD_EXCEPTION。historyUrl仅null或等于baseUrl接受，其他值明确拒绝。OHOS MIME仅token/token，无参数，charset通过独立encoding；historyUrl非空要求非空baseUrl；真实内核charset/history/Unicode未验收。Android原样传native MIME/encoding/history，不宣称冷门编码跨端等价。 |
| OS/SDK边界 | iOS常规网页15+，受控原生chooser18.4+；旧系统开启明确Unsupported，关闭时DOM拦截不保证旧WebKit原生上传隔离。MP4-only候选MOV转换校验输入/输出各50MiB，转码过程磁盘不保证硬上限。 |
| OS/SDK边界 | Android两入口共享官方warmup实现；iOS已有noop不能算优化，OHOS无等价入口。Android document-start依内核能力fallback，窗口flag不等于多Tab UI。 |
| 宿主输入 | URL/header/来源/脚本/频道、品牌账号、权限声明、视频控件和业务路由均由宿主提供；navigationPolicy不能授予Bridge信任。 |
| 未验收 | OHOS真引擎file/MIME/charset/history；CMP iOS真实缩放手势；其他OS版本/可访问性优先级、系统字体/暗化视觉、真实文件媒体权限及远程页面业务。 |

Kuikly桥核验基于固定SDK `core`/`core-render-android:2.28.0-2.0.21-ohos` 的sources：`commonMain/com/tencent/kuikly/core/base/event/IEvent.kt`的EventHandlerFn为Unit；`Event.kt:64..83`记录isSync，`BaseEvent.kt:49..53`的Boolean仅表示命中handler；`BridgeManager.kt`的callKotlinMethod无返回值。Android `KuiklyRenderCore.kt:401..428`创建Unit回调并在主队列任务执行中降为异步，`616..621`区分同步/异步调度。此处是已安装固定版本源码证据，不假设后续SDK版本相同。
